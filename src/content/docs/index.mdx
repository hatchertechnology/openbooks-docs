## How the books stay straight

Entries carry a signed amount in integer cents, debit positive and credit negative, and a
transaction is balanced when its entries sum to zero. That invariant lives in a deferred
constraint trigger in Postgres rather than in application code, so no API bug can write
crooked books.

Reports flip the sign on income, liability, and equity accounts so every line on a statement
reads as a positive number.

[The concepts section](/openbooks-docs/concepts/double-entry/) explains the ledger model from the
beginning, for readers who aren't accountants.
